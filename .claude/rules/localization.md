# Internationalization (i18n) & Localization (l10n) Patterns

Canonical home for the i18n/l10n **capacity** discipline + the iOS String-Catalog patterns. Program: `Docs/PLAN_I18N_L10N_PROGRAM_2026-08-15.md` (OVERVIEW #43); decision `Docs/ADR-139`; research `Docs/RESEARCH_I18N_L10N_2026-08-15.md`. Companion always-on site card: `spark-anvil-website.md` § R-SITE-I18N-VIETNAMESE. l10n-content layer: `distributed-narrative.md` § R-MULTILINGUAL-DN (ADR-060).

## R-I18N-READINESS — internationalize NOW (the fixed-cost capacity), even English-only (2026-08-15)

**i18n is a fixed-cost CAPACITY (built once, in the architecture); l10n is a marginal-cost INSTANCE (authored per locale). Every i18n defect is a 1:N bug (one per locale, every release), and almost every expensive failure is an i18n failure discovered during l10n — so build the capacity NOW, even while shipping English-only (the fixed cost is small; the retrofit is brutal; correct Unicode + locale-aware formatting make a monolingual product better).** Author + review every new user-facing string surface (web chrome, iOS UI, generated copy) against these — a violation is a defect on the same footing as a failed dark-mode axis:

1. **Unicode + NFC** — UTF-8 end to end; **`.normalize('NFC')` at every input boundary** (search, form, comparison, dedup) and when authoring diacritic content. NFC is NOT exhaustive → the font must still position combining marks.
2. **Externalize strings behind STABLE KEYS + per-string context** (screen/audience/tone). **NEVER concatenate sentences from fragments** (locks in English word order, destroys translatability).
3. **Messages, not strings** — named placeholders + selection logic in **ICU-MessageFormat syntax** (MF2 Stable since CLDR 47 / ICU 77; `Intl.MessageFormat` is a *proposal*, polyfill only — adopt the SYNTAX now, defer the runtime).
4. **CLDR-backed formatting** — dates/numbers/lists/plurals through `Intl` (web) / `Foundation` (Apple); never reimplement locale data.
5. **BCP-47 end to end** (`vi-VN`, `en-US`) — never conflate language / script / region; a locale is a BUNDLE, not a language.
6. **Layout absorbs ≥40% expansion** — flexible containers, multi-line ready, RTL-mirroring-capable, headroom for stacked diacritics.
7. **Pseudolocalization is the CI gate** (falsifiability, not inspection) — accent + ~40% expansion + delimiters (+ an RTL pass), placeholder-safe (`pseudo-l10n` on web; Xcode Accented/Bounded scheme on iOS). *A team that reviewed the code has done philosophy; a team whose CI runs a pseudolocale build has done science.*
8. **Route l10n by risk; child-facing content is highest-tier (native-speaker sign-off); NEVER raw MT to a child** (inherits ADR-060 hard guardrail). AI drafts/QA/pseudolocalizes; humans sign off; ship reviewed, frozen, deterministic content.

## R-I18N-CULTURALIZATION — culturalization IS pedagogy (2026-08-15)

**Localization is more than strings: screen every kid-facing narrative/example/asset against Kate Edwards' four high-risk culturalization variables — HISTORY · RELIGION/FAITH · ETHNICITY · GEOPOLITICS — and localize names · foods · examples · holidays · social-scripts, because for education software the culturally-particular details ARE the affective hooks that make content learnable ("made for me" vs an import).** Composes with (never replaces) `spark-anvil-website.md` § R-IMAGE-APPROPRIATENESS + § R-SITE-NO-FOREIGN-FLAGS (a culture is a respectful symbol, never a flag) + `trauma-informed-content.md`. The register/address decision (esp. Vietnamese kinship address) is made + documented in a glossary BEFORE translation (see the site card + `Docs/localization/GLOSSARY_VIETNAMESE_REGISTER.md`).

## R-SITE-VI-EN-PARITY — the Vietnamese website MUST remain in PARITY with the English website (2026-08-15)

**Every user-facing EN string on the website MUST have a Vietnamese counterpart authored against the CURRENT EN text — VI parity is a falsifiable, continuously-tracked property, not a promise. A VI string that is MISSING (EN key with no/empty/EN-identical VI), STALE (the EN source changed since the VI was authored), or an ORPHAN (VI with no EN) is a defect on the same footing as a failed dark-mode axis.** Enforced by the parity CONTRACT (ADR-139 Addendum C): the site-side gate `spark-anvil-site/scripts/check-i18n-parity.mjs` (prebuild + Vitest) diffs `dict.ts` EN↔VI keys (completeness) AND recomputes `sha256(NFC(en))` against the committed `src/lib/i18n/.parity-fingerprints.json` (staleness) — so editing an EN string flags its VI STALE until re-verified. Coverage is driven surface-class-by-class (the **Full-Site Vietnamese Parity / VI-Fleet** program, `PLAN_VI_FLEET_PARITY_PROGRAM_2026-08-15.md`; tracked `Docs/REGISTRY_I18N_PARITY.txt` + `scripts/check_i18n_parity.py`, SHAPE-B WARN), riding the ADR-139 dict+toggle capacity — **NO `/vi/` route explosion** (ADR-139 Decision 2). Risk-tiered ownership: chrome/structural UI + adult marketing prose = hub-authored VI ships; **kid-facing learning CONTENT stays native-review-gated — NEVER raw-MT to a child** (inherits `distributed-narrative.md` § R-MULTILINGUAL-DN / ADR-060). Founder-direct 2026-08-15 (*"the Vietnamese website should remain in parity with the English website"*). This is the parity/coverage sibling of § R-I18N-READINESS (the capacity) — the SAME NFC + no-concatenation + ICU-syntax + ≥40%-expansion discipline, applied as a standing coverage guarantee.

**SCOPE = EVERYTHING (founder-direct 2026-08-16: *"full english-vietnamese parity means all R2 audio media, all webclones, all DN-S, all pdf books, everything."*).** "Full parity" is the WHOLE portfolio's user-facing surface, not just the marketing chrome: (a) shared chrome + hub landings (V1/V2, LIVE) · (b) marketing/company prose (V3, hub-shipped) · (c) homepage (V4) · (d) **ALL webclone content** — per-clone kit stems, bespoke landing copy (DV1/DV2) · (e) **ALL DN-S** — every `/cast` + `/story` chapter, cast dialogue, ensemble story (DV1) · (f) **ALL R2 audio media** — every chapter-narration + audio-drama `.m4a` gets a VI voice take (DV3) · (g) **ALL PDF books** — every dual-tier storybook + companion format gets a VI edition (DV4). **The HARD ADR-060 GATE is UNCHANGED and non-waivable even under "everything": KID-FACING content (DN-S chapters/kits/cast dialogue, audio narration, PDF-book prose) VI is NATIVE-SPEAKER-REVIEW-GATED + FOUNDER-GATED + single-flight PAID (TTS/render) — authored/staged `reviewed:false`, never wired live until reviewed, and NEVER raw-machine-translated to a child.** So the expansion widens the tracked COVERAGE GOAL (DV1-DV4 are IN-SCOPE tracked drains in `REGISTRY_I18N_PARITY.txt`, not skips), while execution of the kid-content classes rides the review + paid-gen + founder gates (account-managed, like the Cloudflare/KDP channels) — chrome + adult-marketing prose continue to ship hub-authored now. A session that raw-MTs kid-facing DN-S/audio/book content to VI is a defect on the ADR-060 hard-guardrail footing, not "progress toward parity." Decision: ADR-139 Addendum F.

**CLIENT-RENDERED chrome uses the shared observer runtime, NOT a bare `data-i18n` (q-e6e04b, 2026-08-17).** A label a client SCRIPT sets via `textContent` AFTER load (feedback rails, late islands) or a STATE-DEPENDENT label (Like↔Liked) MUST translate via `window.saI18n.t(key[,vars])` + re-render on the `sa:homelang` `CustomEvent` the `HomeLangToggle` observer dispatches on `apply()` — a one-shot `[data-i18n]` swap gets clobbered/mis-stated. Runtime exists only on pages carrying `HomeLangToggle` (leaner layouts like `/cast` stay EN — tracked `q-9cf0ea`). Reference: `MostLoved`/`LikeButton`/seasonal intros (site #2372).

**DV1 DELIVERY (learning-CONTENT VI) — the staging + overlay convention (ADR-139 Addendum G, 2026-08-16).** Chrome VI rides `dict.ts`+`data-i18n`; DV1 is CONTENT (kit JSON stems/options/feedback, chapter MD prose, cast dialogue) and needs its own delivery, modeled on the shipped L1-scaffold pipeline: (1) staged in the hub at `Docs/localization/vi/<app>/<app>.dv1.vi.json`, `reviewed:false` (mirrors `<app>.l1.vi.json`; the `.dv1.` infix keeps it disjoint so L1 lanes and DV1 lanes run §5f-disjoint); (2) a per-item TEXT overlay keyed by the base kit item's stable `id` — the base EN kit stays the source of truth for LOGIC (correct answer, indices, Bloom); each item carries the VI fields (`promptVi`/`correctAnswerVi`/`distractorsVi`/`hintsVi`/`explanationVi`) OR `enOnly:true`+`conceptGloss` where the English IS the content (wordplay/phonics — the ADR-060 decodeforge precedent; `enOnly` items are correctly-handled, NOT gaps); (3) NFC + Southern-VI teacher register + proper-noun/code/`$`/symbol EN discipline; (4) the site RENDER-PATH (lift `reviewed:true` overlay into `src/data/play/<app>/` → round shell overlays VI keyed by item id when `sa:homeLang=vi`, EN logic untouched, missing item falls back to EN, `speak()` `vi-VN`) is a turnkey SPEC BUILT at the WIRING wave POST native-review — a `reviewed:false` overlay is NEVER served in production; (5) tracked by `Docs/REGISTRY_DV1_COVERAGE.txt` + `scripts/check_dv1_coverage.py` (SHAPE-B). Drain order = worst-first by pedagogical-cluster priority (Logic→Math→ELA→Science→SS→tail), round-robin at the app grain, kit stems first; FREE in-session Opus (no Gemini key), single-flight-safe. **Canonical builder = `scripts/dv1_build.py`** (reads the EN kit at `Resources/Questions/<app>/<stem>.json`, zips the in-session-Opus-authored VI spec — a JSON list IN EN ITEM ORDER — onto each item's stable `id`, NFC-normalizes, guards count-match + required-fields, always writes `reviewed:false`; `--merge` adds a kit to an existing app file) — use it rather than a per-app `/tmp` builder or hand-copied UUIDs (it removes the UUID-copy + count-slip error class). Reference: logicquest kit_01 (Wave-1 pilot) + proofquest/sleuthlab/cipherforge/coderealm/debateforge (25 translated each) + riddlerealm (the `enOnly`-wordplay reference: 15 translated + 10 `enOnly`+conceptGloss).

## R-SITE-MULTILANG-PARITY — the website-parity mechanism is LANGUAGE-AGNOSTIC (EN↔{N}); es·fr·pt·uk·hi are first-class parity langs alongside vi (2026-08-17, ADR-152)

## iOS String-Catalog patterns (learned from CubeSensei)

- **`Text(verbatim: "AppName")`** — prevents accidental translation of the app/brand name; mark brand names `shouldTranslate: false` in the `.xcstrings`. Algorithm/math/technical notation also use `Text(verbatim:)`.
- **`String(localized: "key")`** — required for non-`Text` usage (`AccessibilityNotification.Announcement`, share text, notification content); SwiftUI `Text("key")` auto-lookup ONLY works in `Text`.
- **Symbol collision** — two keys differing only in capitalization generate the same symbol; use identical casing or remove one (also in `warnings.md`).
